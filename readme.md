# Polymerase Chain Republic（PCR）

96ウェルプレートの試料配置、電気泳動画像のバンド定量、再PCRの管理、等量プールの分注量計算を行うアプリです。配置結果を印刷用HTMLとして出力できます。

公開URL: https://polymerase-chain-republic.vercel.app/

画面・出力ファイル・APIの正式名称は Polymerase Chain Republic、略称は PCR です。既存データとの互換性のため、保存キー、IndexedDB名、JSONの `platepack` フィールド、固定サンプルID、解析バージョン、`PLATEPACK_DB_PATH` と既定DBファイル名は維持しています。

## プロジェクト内の統合フロー

ホームはメンバー・プロジェクトを左の階層と右の一覧で開くファインダー形式です。プロジェクトの直下に記録と出力プレートを表示し、「入力中／作業中／編集完了／非表示」で切り替えます。従来のDB・ブラウザ保存の記録も同じ一覧に表示します。

1. 「新しく登録」で名前を入力し「登録」すると、同じ名前の記録を作成して入力プレート画面を開きます。
2. 入力はブラウザとDBへ自動保存します。「入力中」から再開できます。記録ごとに下書きを分け、古い画面からの上書きは止めます。
3. 配置を設定して「出力」すると、同じ記録IDのまま出力を確定し、作業中のプレート一覧へ戻ります。出力後の元データは入力画面から上書きできません。配置修正は履歴付きの編集プレートとして保存します。
4. 各プレートの「＋ → 泳動写真を登録」で画面内に画像登録タブを開きます。「画像を選択 → 登録」でグレースケールのTIFF／PNGを添付します。元ファイルは分割・ハッシュ照合して永続保存し、同じプレートへの同一画像の重複登録を防ぎます。
5. 画像登録タブの「バンド定量を開く」、添付一覧の「定量を開く」、保存済み解析のリンクはいずれも画面内の定量タブで開きます。DB保存してもタブは開いたまま、保存した解析をプレートの下に反映します。タブ切替でROI・メモ・測定結果を保持し、定量の下書きは画像／解析ごとの保存先に分けます。物理プレートの元IDに画像を紐づけるため、編集完了や非表示、配置の編集後も対応を保持します。

プレートの「編集完了」「非表示」「作業中に戻す」は既存の表示状態・編集履歴と共通です。記録の下には小さな96ウェル図を横並びで表示します。図を押すと同じ画面内の編集タブを開き、複数のタブを切り替えても編集中の内容を保持します。「編集完了」は保存内容の照合後にそのタブを閉じて一覧を更新します。未保存のタブを閉じる場合やページを離れる場合は確認し、保存処理中は閉じる操作を止めます。記録の「開く」では、その記録のプレートをそれぞれタブで開きます。独立した4モードの入口は表示せず、一覧と各記録の編集・定量画面を行き来します。従来の記録URLも引き続き開けます。

追加APIは `/api/workflow/registrations`（名前付き入力の作成）、`PUT /api/workflow/registrations/{id}`（更新日時の照合付き入力保存・出力確定）、`/api/workflow/attachments`（画像の添付・一覧）、`/api/workflow/attachments/{id}/file`（元画像の取得）です。入力の状態は既存ログの `workflow` メタデータ、添付は `workflow_attachments` テーブルに保存します。既存のログ・画像を一括変換しません。

## API 仕様

- **HTTP Method:** `POST`
- **Endpoint:** `/generate-html`
- **Headers:** `Content-Type: application/json`
- **Body:** 下記 `ReportRequest` 構造
- **Response:** `text/html; charset=utf-8`

### リクエスト JSON (`ReportRequest`)

```jsonc
{
  "title": "Plates Packing Report",
  "analyst": "A. Analyst",            // 任意
  "run_date": "2024-10-20T15:00:00Z", // 任意 (未指定時は現在時刻)
  "notes": "任意のメモ",
  "sources": [
    {
      "plate_id": "SRC-001",
      "wells": ["A1", "A2", "B1"],
      "description": "Positive controls"
    }
  ],
  "destinations": [
    {
      "plate_id": "DEST-001",
      "rows": 8,
      "cols": 12,
      "assignments": [
        {
          "well": "A1",
          "source_plate": "SRC-001",
          "source_well": "A1",
          "label": "Control A"       // 任意
        }
      ]
    }
  ],
  "plan": [
    {
      "source_plate": "SRC-001",
      "source_well": "A1",
      "destination_plate": "DEST-001",
      "destination_well": "A1"
    }
  ]
}
```

ポイント:
- `sources[].wells` は元のプレートに含まれる陽性ウェル一覧。個数は統計情報に表示されます。
- `destinations[].assignments` は各デスティネーションプレートの配置。`source_plate` / `source_well` を指定すると自動的に凡例とラベルが付きます。
- `plan` を省略した場合は `assignments` から自動生成します。
- ウェル表記は `A1` 形式に対応しています（大文字・小文字は自動で補正）。

## ブラウザコンソールの使い方

1. ブラウザで `http://localhost:8000/` を開く
2. `PlatesPackerへ` からウェル選択・レイアウト設定・パッキングを実行
3. 必要なら `DB保存` でログ保存、`保存したログ` から読み込み/JSONダウンロード

## 増殖週の記録と保存

- 入力プレート上部の `Growth week` に1〜5週目のボタンを常設しています。週を選んでウェルを押すと、その週番号を記録します。
- 選択済みのウェルを別の週で押すと週番号を変更します。同じ週で押すと選択を解除します。行・列の一括選択も選択中の週を記録します。
- パック後は各ウェルの右下に番号を表示します。PNG、TSVの `*_growth_week` 列、HTMLレポートにも週番号を出力します。
- 入力、メモ、レイアウト、週番号、パック結果はブラウザへ自動保存し、再読み込み時に復元します。ブラウザの2種類の保存先に記録し、直前の下書きも保持します。
- `DB保存` はブラウザとDBへの保存を試み、DBから読み戻して内容を確認します。同時にJSONバックアップをダウンロードします。保存に失敗した場合は失敗を表示します。
- `JSON ↓` で任意の時点のデータを書き出し、`JSONを開く` またはDatabaseのインポートで復元できます。従来のversion 1ログも読み込み可能です。
- ブラウザのデータ削除・端末故障に備えて、JSONバックアップは別の場所にも保管してください。ブラウザだけの保存は別端末に引き継がれません。
- VercelのDB保存には既存のPostgreSQLを使用します（`POSTGRES_URL` / `POSTGRES_URL_NON_POOLING` / `DATABASE_URL`）。未設定・接続失敗の場合はDB保存成功と表示せず、`/tmp`の一時DBにも保存しません。`GET /api/storage-health` で利用可否を確認できます。
- 英数字はデジタル機器風の太字Oxaniumを使用します。OFLライセンスのフォントを同梱し、日本語はゴシック体へフォールバックします。

## Databaseのフォルダ整理

- 人物フォルダの下にプロジェクトを作り、その中に保存したプレートデータを置きます。既存のDBログとブラウザログは「研究者 1 → プロジェクト 1」へ引き継ぎます。既存のID、名前、保存日時、ウェル・週番号等の内容は保持します。
- 「＋」で人物を、「＋ プロジェクト」で配下のプロジェクトを作れます。フォルダ・プレートデータは「名前を変更」で変更可能です。
- Databaseはリスト表示です。サイドバーまたはフォルダを開いて階層を移動し、プレートデータはダブルクリックまたは「開く」でPackerに読み込みます。
- プレートデータをサイドバーのプロジェクトへドラッグすると移動します。Alt/Optionを押しながらドラッグするとコピーします。「移動先」の選択でも移動できます。
- コピー・切り取り・ペーストのボタンと、⌘/Ctrl+C・X・Vに対応しています。操作はPolymerase Chain Republic内のプレートデータに適用します。⌘/CtrlクリックとShiftクリックで複数選択、⌘/Ctrl+Aで表示中の全件選択ができます。
- コピーは新しいIDを作り、元のデータを残します。移動は所属プロジェクトだけを変更します。DBとブラウザの保存データは保存先欄で区別します。
- Packerの「プロジェクト」でDB保存の保存先を指定できます。DatabaseのJSONインポートは現在開いているプロジェクトに保存します。
- ブラウザだけで作成したフォルダは、DBへ接続できる次回Database表示時に同じIDで同期します。DBへの保存ができない場合は画面に表示し、ブラウザのデータを保持します。

## 電気泳動ROIとウェルの手動対応

Packerの「ROI対応」から、PCR Electrophoresisで保存した解析JSON、または台帳一式JSONを読み込みます。
画像のROIをクリックするか番号を選び、元プレート／パッキング後のプレートのウェルをクリックすると対応が保存されます。
表記はA1〜H12です。「指定後に次のROIへ」を有効にすると連続して入力できます。
パッキング後のウェルを選んだ場合も、元プレート番号と元ウェルまで記録します。
未検出・微弱ROIも選択でき、番号は削除・繰り上げしません。同じ泳動内の同じ元検体の重複指定は拒否します。
実際に検体がないROIだけ「空レーン」に指定してください。未検出検体は元ウェルへ対応づけたまま扱います。

対応は下書きの自動保存、DB保存、JSON ↓に含まれます。画像プレビューは保存しますが、
定量用の元画素とPCR Electrophoresisの全履歴はPolymerase Chain Republicへ複製しません。
Polymerase Chain Republicを再読み込みした後にPCR Electrophoresis用JSONを書き出す際は、その画像の元の解析JSONを再読み込みしてください。
同じ画像の再読み込みではROI番号ごとの対応を維持し、測定結果と位置を更新します。

「対応済みPCR Electrophoresis JSON」で出力したファイルをPCR Electrophoresisの「解析を開く」で読み込み、分注台帳へ再登録すると、
サンプル名・元ウェル・Polymerase Chain Republic対応情報が反映されます。ROI位置、ベースライン、原画素とマーカー設定は保持します。
明示した空レーンは除外され、番号は残ります。未指定または配置変更で無効になった対応がある場合はPCR Electrophoresis出力を止めます。
途中結果は「対応一覧CSV」に未指定・未検出を含めて出力できます。

再PCRは同じPolymerase Chain Republicのログ／下書き内で別の泳動JSONを読み込み、同じ元ウェルへ対応づけます。
元プレートに持たせた固定識別子とウェルから同じサンプルIDを生成するので、PCR Electrophoresisで同じ検体として照合できます。
初回分も再PCR分も対応済みJSONでPCR Electrophoresisへ登録し直してください。以前の別名とは自動照合しません。
パッキングのやり直しで指定先の元検体が変わった場合や、プレートを削除して作り直した場合は要確認となり、
元の対応を黙って別検体へ付け替えることはありません。

検証: `node --test tests/gel-links.test.cjs`（ROI保持、元ウェル解決、重複拒否、再PCRの同一ID、
配置変更・プレート置換の検出、再読込、PCR Electrophoresis出力、空レーン、保存形式の検証）。

## Electrophoresis — 泳動画像から分注計画まで

プロジェクトの泳動画像、または保存した解析から開きます。プレートと対応していない画像も、面積取得・分注量計算・CSV出力に使えます。
TIFF / PNGを登録し、最大ROI数を指定すると、バンド候補を上限まで抽出します。
現時点の自動配置は「左端にラダー、右にサンプル」の複数段ゲル向けです。
8 / 16-bitの単一ページ・グレースケール画像（3000万画素以下）を使用してください。

1. 「バンド・分注量」でバンドをクリック、または一覧にチェックを入れます。面積・相対値・分注量をその場で表示します。
2. 基準バンド、基準液量、丸め刻みを調整します。ウェル対応やマーカーの確認、計算案の確定は不要です。
3. 必要に応じて名前を付けた計算セットを複数作成して組み合わせを比較し、「分注 CSV ↓」で直接書き出します。
4. ROIや背景線を修正する場合は「ROI編集」に切り替えます。面積を更新したら、選択したバンドの液量も更新します。
5. 「DB保存」で画像・ROI・計算セットを保存します。「別のブラウザタブで開く」で未保存の作業も引き継げます。

### 選択したバンドの分注量

「バンド・分注量」では画像上のクリック、または一覧のチェックで対象バンドを選びます。
面積は元画素の背景補正積分で取得し、ウェル対応・マーカー・手動確認・計算案確定を前提にしません。
「要確認」「再PCR」「除外候補」などは参考表示であり、計算への参加はチェックの有無だけで決まります。
同じ元ウェルの再測定でも自動で一本にまとめず、選ばれたバンドを個別の行として扱います。

基準面積は選択バンドの最大・最小・中央値、または任意の一本から選べます。
相対値 = 面積 / 基準面積、分注量 = 基準液量 / 相対値です。
1–20 µLを超えても除外・切り詰めをせず、数値と目安を表示します。丸め刻み0は丸めなしです。
面積0や再抽出で失われたROIは液量を空欄とし、理由を表示します。他の行はそのまま計算します。
計算セットは作成時に好きな名前を付けられ、セット名欄から後で変更できます。複数の計算セットを作成でき、CSVを直接保存できます。セットは解析のDB保存・実験JSONにも含みます。

「プレート PNG ↓」で96ウェルの図をプレビューし、各ウェル内に分注量を入れたPNGを保存できます。
登録済みの対応では出力プレートまたは入力プレートの実際の位置を使います。対応がない場合はROI番号順の仮配置、または選択順の新しい配置を明示的に選べます。横方向・縦方向を切り替えられ、複数のプレートも選択して個別に保存できます。
未配置の件数は図と画面に表示し、同じウェルに複数の結果がある場合も自動合算せず、欄外に個々の値を表示します。計算不可と0 µLは区別します。

面積の取得はROIの位置・幅・高さ・背景線などが変わった場合だけ行います。
バンドの選択や基準液量の変更では元画像を再送せず、取得済みの面積からブラウザ内で即時計算します。
「別のブラウザタブで開く」は未保存の選択・ROI・画像を引き継ぎ、引き継ぎ先の準備完了後に元の埋め込み画面を閉じます。

### 原画像・保存方式

元画像と実験記録はSHA-256で照合し、256 KiBずつ転送してSQLiteまたは既存のPostgreSQLに保存します。
`gel_chunks` / `gel_blobs`を追加し、実験ログから参照します。サーバーの一時ファイルやメモリキャッシュには依存しません。
別メンバー／プロジェクトへのコピー・移動でも参照は維持します。ログ削除時に元画像を巻き添えで消しません。
Vercelでの永続保存には従来どおりPostgreSQLの設定が必要です。画像は1ファイル96 MiBまで、1実験32画像までです。
「実験一式JSON」は元画像も含む持ち運べるバックアップです（取り込み160 MiBまで）。「元画像」から無加工のTIFF／PNGも取得できます。
プレビューは表示専用に最大2048pxへ縮小し、必要時のみJPEG化します。元画像・測定精度は変わりません。

### 表示と互換性

日本語・英数字は一般的なシステムフォント、文字サイズは原則28 / 22 / 16 / 14 / 12 pxです。
Growth phaseは1〜5の色と右下の番号で記録します。出力プレートの元プレート色と右下のフェーズ番号も維持します。
既存ログとの互換性のため、保存キー`growthWeeks` / APIキー`growth_week`は維持しています。
新規プロジェクトはPackerの保存先の横からも作成できます。

検証: `python -m unittest discover -s backend/tests -q` と `node --test tests/*.test.cjs`。
数値計算、最大集合の全探索との比較、マーカーによる露光補正、再PCR照合、16-bit保持、画像分割転送、保存・コピー・移動を検証します。
ImageJとの直接比較・希釈系列による実験的な精度検証は未実施です。

## 作業画面

- Packerは「入力 → 配置 → 結果」を切り替えて操作します。配置に成功すると結果へ移ります。保存先は「保存」、TSV・PNG・JSONの入出力は「ファイル」にあります。
- Electrophoresisは「実験」でプロジェクトとプレートを指定し、「画像／ROI／測定／プール」を切り替えます。ROI設定はダイアログ、バンド編集は選択時のパネルで開きます。切り替えは測定値やROIを変更しません。
- Databaseのコピー・移動・名前変更などは「操作」にまとめています。
- 説明は対象のボタンへポインターを合わせるか、キーボードでフォーカスしたときに表示します。設定やメニューはクリックでも開けます。

## 出力プレートの編集

HomeまたはDatabaseの「出力プレート」からプロジェクトごとの配置を確認できます。サムネイルを押すと1枚を拡大し、チェックボックスで最大2枚を選んで「編集」を押すと並べて表示します。

- 単独ウェルを空ウェルへドラッグすると移動、試料のあるウェルへドラッグすると交換します。元の入力プレート・ウェル・Growth phaseを試料と一緒に保持します。
- 「範囲選択」でドラッグ、またはShift＋クリックすると長方形を選択します。選択範囲のウェルをドラッグすると配置を保って移動します。範囲内の空ウェルも含め、移動先がすべて空の場合のみ許可します。占有範囲との重なり・範囲外への移動は配置を変えずに拒否します。
- 「移動先を選ぶ」はドラッグの代わりに移動先をクリックする操作です。「削除」は編集版の出力ウェルを空にし、元データの入力試料は削除しません。
- 「戻す」（Ctrl / ⌘ + Z）は直前の操作を取り消し、「リセット」は編集開始時に戻します。リセット自体も取り消せます。未保存で画面を離れると確認します。
- 保存は元データを上書きせず、`プロジェクト → 元データ → 編集プレート → 元の名前_ed`に表示する独立した記録を作ります。別々の元データの間で移動した場合は、両方の出力配置を1レコードにまとめて保存し、両方の元データの下から開けます。選択していない出力プレートも元の配置のまま引き継ぎます。再編集して保存すると新しい記録ができ、日時で区別できます。
- 保存時はサーバー側で変更履歴を再生し、試料の配置と一致することを検証します。保存後に再読込して全内容を照合してから「保存済み」と表示します。
- 泳動のプレート選択では編集プレートを先頭に表示します。編集後の出力ウェルにROIを紐付け、元サンプルの識別子は版や泳動実験をまたいで維持します。編集プレート由来の測定結果のウェル表示は実際の出力先です。過去の泳動解析は保存時点の配置を保持します。

編集履歴・元データへの参照はプレートのJSONに保存します（`recordType: edited_plate`, `plateEdit`）。新しいDBテーブルや破壊的な移行は不要です。DBと内容が同一のブラウザバックアップは出力プレート総覧では重複表示しません。

### ファイルの保存先

PNG・CSV・TSV・JSON・元画像は、対応ブラウザで保存先とファイル名を毎回選択して保存します。保存ダイアログを開いてから画像生成やファイル取得を始めるため、キャンセルした場合はダウンロードしません。複数のJSONを選択した場合は、ファイルごとの保存ボタンを表示します。
保存先選択APIのないブラウザでは設定の案内を表示します。ブラウザの「保存前に保存先を確認する」設定を有効にしてください。サイトからこのブラウザ設定を変更することはできません。
